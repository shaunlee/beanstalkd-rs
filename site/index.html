Features

Everything beanstalkd does.
Plus what production needs.

One binary, no runtime dependencies, MIT.

  • Drop-in compatible

    Every command, reply and edge case matches the reference, checked by 222 differential tests.

  • Faster, on less CPU

    1.2–1.4× the throughput at 10–100 connections, with 10–24% less CPU per operation.

  • TLS and authentication

    TLS, mutual TLS and token authentication per listener. No proxy in front.

  • Observable

    Prometheus /metrics, /healthz, /readyz and a JSON /admin endpoint.

  • Raft replication

    Optional 3 or 5 node cluster over mutual TLS. Keeps serving through the loss of a minority.

  • Graceful shutdown

    SIGTERM stops accepting, syncs the log and exits 0.

Performance

Same fsync. 2.2× the throughput.

Operations per second at 100 connections, beanstalkd against beanstalkd-rs. Higher is better.

Linux 7.0 (aarch64) on an Apple M6, both servers with default settings, medians of 5 alternated runs. One connection is latency-bound, where beanstalkd-rs is 4% slower on Linux. Every cell, the method and the raw data: docs/BENCH.md.

Get started

Up in one command.

$ docker run -d --name bstk -p 127.0.0.1:11300:11300 -v bstk-data:/data \
    shonhen/beanstalkd-rs -l 0.0.0.0 -p 11300 -b /data
$ cargo install bstkd        # or: cargo binstall bstkd
$ beanstalkd-rs -l 127.0.0.1 -p 11300 -b ./binlog

Linux x86_64 and aarch64 (glibc or static musl) and macOS aarch64. Each archive holds the binary, a systemd unit, example configurations, the cluster certificate script and the operations guide.

Migrating from beanstalkd

Point existing clients at it and they work unmodified. The binlog format differs, so drain the old server and switch.
