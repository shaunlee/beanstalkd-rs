beanstalkd-rs

A drop-in replacement for beanstalkd, the simple work queue, written in Rust. The protocol is the reference's, byte for byte, so existing clients work unmodified.

What you get for switching

  • Faster, on less CPU

    1.2–1.4× the throughput at 10–100 connections and 2.2× with a binlog and fsync, with 10–24% less CPU per operation.

  • Production features built in

    TLS, mutual TLS and token authentication per listener, Prometheus /metrics, /healthz, /readyz, a TOML configuration file and graceful shutdown, with no proxy in front.

  • Optional Raft replication

    3 or 5 nodes over mutual TLS. Clients connect to any node, a minority can be lost, and nodes can be added, removed or moved while the cluster serves.

  • Checked against the reference

    unsafe forbidden at the workspace level, 222 differential test cases against the C reference, and the Python, Go and PHP (Pheanstalk, the client behind Laravel's queue driver) clients compared transcript-to-transcript against it.

One binary, no runtime dependencies, MIT.

Try it

Docker (linux/amd64 and linux/arm64; also ghcr.io/shaunlee/beanstalkd-rs):

docker run -d --name bstk -p 127.0.0.1:11300:11300 -v bstk-data:/data \
  shonhen/beanstalkd-rs -l 0.0.0.0 -p 11300 -b /data

Or from crates.io (Rust 1.98 or newer; the binary is called beanstalkd-rs):

cargo install bstkd        # or: cargo binstall bstkd
beanstalkd-rs -l 127.0.0.1 -p 11300 -b ./binlog

Release archives for Linux x86_64 and aarch64 (glibc or static musl) and macOS aarch64 are on the releases page. Each holds the binary, a systemd unit, example configurations, the cluster certificate script and the operations guide.

Migrating from beanstalkd

Point an existing client at beanstalkd-rs and it works, including the reference's parser quirks.

The binlog directory is not compatible. beanstalkd-rs uses its own on-disk format, so a migration drains the old server and switches rather than swapping the binary under a full queue. The README has the steps, and docs/COMPAT.md lists every intentional behavior difference with the test that covers it.

When something else fits better

  • Consumer groups, streams, replay or fan-out to independent consumers: NATS, Kafka or Redis Streams model that; tubes do not.
  • A managed service and no operations: SQS, Cloud Tasks or a hosted RabbitMQ.
  • Beanstalkd's exact on-disk binlog format: this project deliberately does not keep it.
